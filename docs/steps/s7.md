# S7 多轮对话

目标：把左侧面板从「一次性表单」改成「会话对话流」——同一会话里可以继续追问、继续生成，每次生成自动成为下一版；追问由规则判断，不需要额外 LLM 调用。

## 数据模型

只新增两张表，历史库升级时 `CREATE TABLE IF NOT EXISTS` 直接生效，无需 `ALTER`：

```sql
CREATE TABLE sessions (
  id TEXT PRIMARY KEY, title TEXT NOT NULL, created_at TEXT NOT NULL, updated_at TEXT NOT NULL
);
CREATE TABLE messages (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id TEXT NOT NULL,
  role TEXT NOT NULL,        -- user|assistant
  kind TEXT NOT NULL,        -- text|question|artifact|error
  content TEXT NOT NULL,
  task_id TEXT,              -- kind=artifact 时指向任务
  created_at TEXT NOT NULL
);
```

会话与版本的关系：每次生成仍是一个 `tasks` 记录，`parent_id` 取**本会话最近一次成功产物**。跨会话不会串版本。

## 澄清规则（`app/planner.py`）

按顺序判断，命中即追问：

1. 历史里已经有 `question` 消息 → **不再拦**，直接生成；
2. 累计用户输入为空 → 追问"核心功能 / 配色"；
3. 命中模糊表达（`做个网页`、`帮我搞个应用` 这类）→ 追问"具体做哪一类"；
4. 累计不足 12 字 → 追问"再补充一点"；
5. 其余放行生成。

追问只发一条 `assistant/question` 消息，不建任务，因此不消耗生成额度。

## 上下文注入

`build_prompt(history, requirement)` 把历史拼成「用户：… / 助手：…」纯文本，跳过产物卡片，超过 1200 字符保留最近部分。拼好的文本作为 `engine_prompt` 在内存里传给引擎，**不落库**；`tasks.prompt` 仍是用户这一轮的原话，保证任务详情、列表和验收断言不被污染。

## 已知边界

- 澄清是规则判断，不是 LLM 判断：极简但合法的需求可能被放过（直接生成）；反向也可能多问一次。LLM 澄清留了 `clarify()` 口子（design.md 4.7）。
- 消息流靠 1.5s 轮询，没有流式输出。
- 真机 MetaGPT 未验证：本轮的多轮上下文只在假包下确认了"确实拼进引擎输入"，产物质量仍需服务器上跑一次真 key。
