# S4 · 接入 MetaGPT 引擎（可切换 MOCK）

## 这一步做了什么

S3 的链路（入队 → 状态机 → 产物扫描 → 预览）已经跑通，缺的只是"谁来生成"。这一步把引擎层补成两个可互换的实现，并把选择权交给环境变量：

| 文件 | 变化 |
|---|---|
| `app/engine/metagpt_engine.py` | **新增**：懒加载 MetaGPT，单角色产出单文件 HTML，可被取消 |
| `app/config.py` | `MOCK_ENGINE` 改为三态 `auto / mock / metagpt`，`Settings.engine_mode` 取代布尔值 |
| `app/tasks.py` | 引擎选择支持 auto 降级；收尾顺序修正（先落终态再写产物元数据） |
| `app/api.py` | `/health` 增加 `engine_mode` 字段（实际生效的实现仍看 `engine`） |
| `app/__init__.py` | 版本 `0.4.0`、`STEP = "s4"` |
| `scripts/gen_once.py` | **新增**：命令行单次生成，绕过 Web 与数据库直接调引擎 |
| `scripts/seed_demo.py` | **新增**：预置演示任务，直接写库 + 本地跑 MOCK |
| `scripts/verify_s4.sh` | **新增**：15 项验收，含隔离实例上的超时路径 |
| `scripts/verify_s2.sh` | 步骤号改为"不低于 s2"、路由隔离改用永不实现的路径（否则 S4 起回归误报） |
| `deploy/atoms.service` | 去掉写死的 `MOCK_ENGINE=1`，默认走 auto |
| `web/index.html` | 版本 chip 与帮助面板改为 S4 说明 |

## 引擎选择（三态）

| `MOCK_ENGINE` | 行为 | 用在哪 |
|---|---|---|
| 留空（默认） | **auto**：能 `import metagpt` 就用真实引擎，否则降级 MOCK 并记 warning | 交付环境，装没装依赖都能跑起来 |
| `1` | 强制 MOCK | 本地回归、演示兜底、无额度时 |
| `0` | 强制真实引擎，装不上直接报错（不静默降级） | 明确要验证真实生成时 |

`/health` 会同时返回两个字段，排查时一眼能看出"配置要什么"和"实际生效什么"：

```json
{"engine": "mock", "engine_mode": "auto", ...}
```

## 真实引擎实现要点

- **懒加载**：`app/` 顶层不 import metagpt；`metagpt_engine.py` 内部也只在函数里 import，模块本身可安全导入（`metagpt_available()` 负责探测并返回失败原因）。
- **单角色，不用 Team**：自定义 `BuildPage(Action)` + `Builder(Role)`，一次 `role.run(Message(...))`；不跑多角色全流程，时延可控（design 4.3 的取舍）。
- **API 漂移兜底**：Role/Action 路径抛 `ImportError/AttributeError/TypeError` 时，退回 `metagpt.llm.LLM.aask()`，并在日志里记 `mode=llm`。
- **提示词固定**：只输出单文件 HTML、不引用外部资源、深色响应式、中文界面。压低自由度是为了让 `scan_artifacts` 稳定找到入口，也避免预览被 CDN 拖垮。
- **HTML 提取**：优先取 ```html 代码块，其次全文；从第一个 `<!doctype>`/`<html` 截到最后一个 `</html>`；提取不到就抛错（任务判失败，不产出空文件）。
- **可取消**：全程 `await`，不吞 `CancelledError`；超时/取消由编排层的 `asyncio.wait_for` 与 `handle.cancel()` 负责。
- **产物**：只写 `index.html` 与 `meta.json`（引擎版本、模式、原始字符数、耗时），不改数据库。

## 失败 / 超时 / 取消路径

| 情形 | 结果 | 用户看到 |
|---|---|---|
| 引擎抛异常 | `failed`，`error` 截断 500 字 | 红色横幅 + 原因 + 「重试」 |
| 超过 `TASK_TIMEOUT`（默认 600s） | 协程被取消，`failed`，`error=timeout after 600s` | 同上 |
| 用户点取消 | `cancelled`，不回滚已写文件 | 阶段卡片标红，预览显示「任务已取消」 |
| 进程退出 | `failed`，`error=interrupted` | 刷新后可见，不会永远转圈 |
| 收尾时被取消 | 取消方赢，不写产物元数据 | 状态与产物一致（S4 修的竞态） |

## 两个命令行工具

```bash
# 单次生成：排查"引擎到底能不能出 HTML"，不碰数据库
python scripts/gen_once.py "做一个番茄钟，深色主题"
python scripts/gen_once.py "做一个待办清单" --engine mock
python scripts/gen_once.py "做一个记账面板" --engine metagpt --timeout 900
python scripts/gen_once.py "验证失败路径" --fail        # 故障注入，退出码 1

# 预置演示数据：直接写库，服务重启后列表里就有
python scripts/seed_demo.py --count 2
python scripts/seed_demo.py --dry-run
python scripts/seed_demo.py --prompt "做一个日历" --force
```

`gen_once.py --engine metagpt` 在没装 MetaGPT 的环境会输出一行可读提示并退出 1，不打印 traceback。

## 怎么部署

S4 本身不改依赖清单，**装不装 MetaGPT 都能部署**：

### 方案 A：先跑 MOCK（推荐先做，10 分钟）

```bash
cd ~/atoms-dev-demo && git pull
bash scripts/deploy.sh          # unit 已不再写死 MOCK_ENGINE，auto 会自动降级
curl -s localhost:8000/health   # {"engine":"mock","engine_mode":"auto"}
bash scripts/verify_s4.sh
```

### 方案 B：接真实引擎

```bash
# 1) 必须是 3.11（3.12 装不上 metagpt 的依赖）
uv python install 3.11
uv venv --python 3.11 .venv
# 2) 取消 requirements.txt 里 metagpt 那行的注释后安装
sed -i 's/^# metagpt==0.8.2/metagpt==0.8.2/' requirements.txt
uv pip install --python .venv/bin/python -r requirements.txt

# 3) LLM Key 只放服务端，不下发前端
metagpt --init-config          # 生成 ~/.metagpt/config2.yaml
#    编辑：api_type=openai, base_url=https://api.deepseek.com/v1, model=deepseek-chat, api_key=sk-...

# 4) 先不经过 Web 验证引擎
.venv/bin/python scripts/gen_once.py "做一个番茄钟，深色主题" --engine metagpt --timeout 900

# 5) 重启服务，确认实际生效的引擎
bash scripts/deploy.sh
curl -s localhost:8000/health  # 期望 "engine":"metagpt"
```

首次真实生成 5–10 分钟属正常，硬超时 600s；2G 内存下先加 2G swap（见 `docs/setup.md`）。

## 怎么验收

```bash
bash scripts/verify_s4.sh                 # 本机
TARGET=public bash scripts/verify_s4.sh   # 只跑服务层（引擎层检查始终在本机执行）
SKIP_TIMEOUT=1 bash scripts/verify_s4.sh  # 跳过超时路径
```

15 项检查覆盖：

- 服务层：`/health` 可用、`engine` 为 mock/metagpt、`engine_mode` 合法、版本 0.4.x
- 回归：建任务 → `succeeded` → 预览 200 → 路径穿越仍 404
- 引擎层：`gen_once.py --engine mock` 产出 `index.html`；`--fail` 返回非 0 且给出原因；没装 metagpt 时 `--engine metagpt` 明确报错；`seed_demo.py --dry-run` 可用
- 超时路径：在 8011 端口起一个 `TASK_TIMEOUT=1` 的隔离实例（独立 `DATA_DIR`/`WORKSPACE_DIR`），建任务后必须变成 `failed` 且 `error` 含 `timeout`，跑完自动清理

人工确认（真实浏览器，本步已用本地 Chromium 走通）：

1. 顶栏 `后端已连接 · S4`、版本 chip `s4`、引擎标签 `引擎 MOCK`
2. 点「帮助」→ 面板标题「这是 S4 版本」，文案说明 `MOCK_ENGINE` 三态与 `gen_once.py`
3. 任务列表里预置的"番茄钟"任务可点开，右侧预览可交互（计数从 0 变 1）
4. 控制台 0 error

## 怎么回滚

```bash
git checkout s3 && bash scripts/deploy.sh
```

S3 的代码读同一份数据库，`tasks` 表没有新增列，产物目录也无需清理；唯一差异是 `Settings.mock_engine` 在 S3 是布尔值（本步改成 `engine_mode`），但那是代码内部结构，不影响数据。

## 本步实测记录与限制

| 项 | 结论 |
|---|---|
| 本机环境 | Windows + Python 3.14，未安装 MetaGPT → auto 降级 MOCK，启动日志有 warning，功能完整 |
| 超时路径 | 隔离实例（`TASK_TIMEOUT=1`）实测：任务 1s 后被置为 `failed`，`error=timeout after 1s` |
| 失败路径 | `gen_once.py --fail` 退出码 1；编排层异常收口与产物目录保留已由 `verify_s4.sh` 的 CLI 用例覆盖 |
| **真实 MetaGPT 生成** | **未在真实 API Key 下验证**：本地是 Python 3.14 且无额度，服务器需按"方案 B"安装后跑 `gen_once.py --engine metagpt` 确认 |
| 单次时延 | 真实生成按 design 预估 5–10 分钟，`TASK_TIMEOUT=600` 可能偏紧；如频繁超时，部署时调大该变量 |
| 产物结构 | 只保证单文件 `index.html`；若模型仍输出多文件，`scan_artifacts` 会挑路径最短的 HTML 作入口 |
| 引擎并发 | 仍为 1（信号量），真实生成期间后续任务保持 `pending`，可取消 |
