# S9：应用存储（存储桥）

## 背景

S8 验收发现：费用工具的记录刷新后丢失。根因是预览 iframe 处于 opaque origin
（`sandbox="allow-scripts"` 无 `allow-same-origin`），生成应用写的 `localStorage` 访问即抛
`SecurityError`。同批验收还发现计算器修复无效（迭代修复不带旧代码上下文）与自检漏检逻辑
bug，这两项属生成管线问题（提示词层），另行处理；本步只解决存储。

## 改了什么

| 文件 | 内容 |
|---|---|
| `app/models.py` | 新增 `task_data` 表（只增不改） |
| `app/db.py` | `ensure_task_data / data_token_matches / get_task_data_raw / set_task_data_raw`；行按版本链根任务（`root_of`）归档，token 比较用 `secrets.compare_digest`；`delete_task` 级联清理 |
| `app/tasks.py` | `start()` 建任务时同步建存储行 |
| `app/api.py` | `GET/PUT/OPTIONS /api/tasks/{id}/data`（ACAO:\*、64KB 限额、token 鉴权）；预览 / `/files/` 子页 / `/p/` 公开页 HTML 服务时注入 `window.__ATOMS__={dataUrl, token}`，产物文件不改动 |
| `app/engine/prompts.py` | CODE_PROMPT 第 6 条：禁 localStorage + 教 `window.__ATOMS__` fetch 持久化用法 |
| `app/__init__.py` | `STEP = "s9"` |
| `scripts/verify_s9.sh` | 15 项验收（注入 / 鉴权 / 限额 / 回环 / CORS 预检 / 版本链共享 / 沙箱约束不变） |
| `docs/design.md` | 4.1 接口表、4.4 注入说明、4.5 表结构、新增 4.9 应用存储节 |

契约细节见 `docs/design.md` 4.9。

## 怎么部署

```bash
git pull && ./scripts/deploy.sh && sudo systemctl restart atoms
TARGET=public bash scripts/verify_s9.sh   # 公网回归
```

老库无 `task_data` 表：`CREATE TABLE IF NOT EXISTS` 自动建；老任务无 token 行：
首次预览/访问时懒创建，无需迁移脚本。

## 怎么回滚

`git checkout s8` 重启即可。新表保留在库里，旧代码不读取，无副作用。

## 验收命令

```bash
bash scripts/verify_s9.sh        # 16 项，不依赖真模型（挑最近可预览的任务）
bash scripts/verify_s8.sh        # s8 回归（本步验证时 38 通过 / 0 失败）
```

写测试前先快照任务现网数据、测完原样恢复，不污染真实任务（2026-11-19 曾因无快照
把 `verify-s9` 测试记录写进用户账目应用，已修）。

浏览器实测（playwright，msedge）：`sandbox="allow-scripts"` 的 iframe 内执行
`fetch(__ATOMS__.dataUrl + '?token=' + __ATOMS__.token)` PUT/GET 均 200 且回读一致；
同一 iframe 里 `localStorage` 抛 `SecurityError`（证实沙箱行为与方案前提）。
版本链子任务与根任务 token 相同、数据互通（迭代不丢数据）。

## 边界与后续

- 令牌是"能力 URL"模型：拿到 task_id + token 即可读写该应用的存储。演示场景够用；
  若要收紧可改为按会话签发短期 token。
- 存储按根任务归档：历史版本预览时看到的是**当前**数据（同一应用一份状态），
  不做"每个版本各自快照"。
- 生成管线问题（迭代修复带父版本代码、自检功能走查）另行在提示词层处理。
