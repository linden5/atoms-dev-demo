# S1 · 静态单页与演示数据

## 这一步做了什么

交付一个不依赖后端、但打开就能交互的单页工作台，用于在最早阶段验证「服务器可达 → 端口放行 → 静态服务启动」这条链路。

新增：

| 文件 | 作用 |
|---|---|
| `web/index.html` | 页面骨架：顶栏、左侧需求/阶段/任务列表、右侧预览 iframe |
| `web/styles.css` | 深色 IDE 风格样式，含设计变量、响应式（<960px 上下堆叠） |
| `web/app.js` | 内置 3 条演示任务（2 条成功、1 条失败）+ 前端模拟生成流程 |
| `deploy/atoms.service` | systemd unit，此阶段用 `python3 -m http.server` 提供静态文件 |
| `scripts/deploy.sh` | 统一部署入口：拉代码 → 同步依赖 → 更新 unit → 重启 → 探活 |
| `scripts/verify_s1.sh` | 本步验收脚本 |
| `.gitignore` | 排除 `.venv`、`workspace/`、`data/`、`logs/` 等运行时目录 |

## 可交互到什么程度

- 点击右上「帮助」查看当前步骤说明，点空白处或 Esc 关闭
- 点击 3 个示例标签，自动填入需求
- 点击任务列表任意一条，右侧预览切换；失败任务显示红色错误横幅 + 重试
- 在需求框输入后点「生成应用」（或 Ctrl / ⌘ + Enter），前端模拟 pending → planning → coding → checking → succeeded，阶段卡片依次点亮，最后渲染一个可点击的演示应用
- 预览工具栏可切换 375 / 768 / 1000 / 自适应宽度，可刷新、可在新窗口打开

注意：这一步的数据全在内存，刷新会重置。持久化在 S3 才引入。

## 怎么部署

```bash
# 服务器上（Ubuntu，仓库已 clone 到 ~/atoms-dev-demo）
cd ~/atoms-dev-demo
git pull
sudo cp deploy/atoms.service /etc/systemd/system/atoms.service
sudo systemctl daemon-reload
sudo systemctl enable --now atoms
sudo systemctl status atoms
```

或直接：

```bash
./scripts/deploy.sh
```

云厂商安全组放行 `TCP:8000`（来源 `0.0.0.0/0`），然后访问 `http://<公网IP>:8000`。

## 怎么验收

```bash
./scripts/verify_s1.sh                                  # 本机
BASE_URL=http://<公网IP>:8000 ./scripts/verify_s1.sh     # 公网
```

脚本检查：首页 200、标题、需求输入框、预览 iframe、sandbox 隔离、任务列表、示例入口、`styles.css`/`app.js` 可访问且含关键实现。任一失败退出码非 0。

人工确认（必须做，curl 只能证明资源在）：

1. 无痕窗口打开 `http://<公网IP>:8000`，页面样式正常、无 404
2. 点示例标签 → 点「生成应用」→ 看阶段卡片依次点亮 → 约 3.4 秒后右侧出现可点击的应用
3. 点第二条任务（待办清单），预览切换，能新增/勾选/删除
4. 点第三条任务（失败示例），出现红色横幅与「重试」

## 本地预览（不想上服务器时）

```bash
# Linux / macOS / WSL
python3 -m http.server 8000 --directory web

# Windows PowerShell
py -3.11 -m http.server 8000 --directory web
```

然后打开 `http://127.0.0.1:8000`，用 `BASE_URL=http://127.0.0.1:8000 ./scripts/verify_s1.sh` 验收（Windows 下在 Git Bash 或 WSL 里执行脚本）。

## 怎么回滚

这一步是首个版本，回滚即停止服务：

```bash
sudo systemctl disable --now atoms
```

## 已知限制（留给后续步骤）

| 限制 | 在哪一步解决 |
|---|---|
| 数据不持久化，刷新重置 | S3（SQLite） |
| 「生成」是前端模拟，没有真实调用 | S3（MOCK 引擎）→ S4（MetaGPT） |
| `http.server` 无缓存头、无 CSP、单线程 | S2 换 uvicorn、S6 加安全头 |
| 任务没有版本链 | S5 |
| 端口 8000 是明文 HTTP | 不解决，改用域名需备案，见 `design.md` 决策记录 |

## 已修问题

| 问题 | 修法 |
|---|---|
| `scripts/deploy.sh` 的 `git pull --ff-only` 在分支无上游时中断，导致首次部署时后续 unit 安装与重启不执行 | 改为先 `git rev-parse --abbrev-ref --symbolic-full-name '@{u}'` 判断上游，不存在时告警并跳过 |

首次部署仍建议先 `git push` 再执行 `deploy.sh`，这样服务器 `git pull` 能真正拿到最新代码。
